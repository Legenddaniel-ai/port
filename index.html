PRINCIPLES

How I think.
principles that shape the work.

01

Ship with intention

Before writing code, I ask what problem it solves and who it solves it for. If I can't answer both, the feature doesn't get built.

02

Systems over pages

I think in components, data contracts, and module boundaries rather than just screens. Good architecture lets the product grow without requiring rewrites.

03

Design is engineering

I don't hand off between design and code. I own the full surface, from the database schema to the hover state. If I designed it, I built it.

04

Move fast, stay clean

I write code I'd want to inherit: readable, tested, documented. When I set up shared component libraries, other projects reuse them for months. Technical debt is a choice, not a given.
